# 工作流v5.2

## 理论

这里讲的「理论」是抽象程度比较高的一层：为什么这样学、以什么状态学、为什么这样使用工具。这一层想清楚了，下面的具体工具和操作才有依据。

### 引言

> [!quote] 沃兹基硕德
> 当一个人经历长时间的忙碌后，他的短暂闲暇往往不会用来休息，而是反思如何修改他的工作流使得下一次的忙碌可以在更短的时间结束。

如果你是一个具有逻辑思维的人，或者有强大洁癖的人，你会非常希望把自己的一切体系化和模块化，这样才方便维护和补充（如果说得工程规范一点的话），对于学习方法和工作流也是一样，下面我会先讲清楚理念层面的东西，再给出我最新使用的工作流。

通常来说，我们从开始上学到高中毕业的学习方式都可以归结为一套简单的理论体系，也就是 GTD(Get Things Done)。它是一种高效的时间管理和工作流程方法，由 David Allen 提出并广泛应用于个人和组织中。GTD 的核心理念是通过记录和管理所有任务，将任务从大脑中解放出来，以减少焦虑并提高效率。它的基本步骤如下所示：

> 这里只是给出一个非常简单的说明，并不会详细的介绍，因为这种方法对我并不 work 我也并不是很喜欢，这里提到只是因为学校主要培养的是这种理论体系。

1. **收集**：将所有需要处理的信息和任务记录在一个“生肉库”或“收件箱”中，无论是邮件、想法还是待办事项，都要无遗漏地收集起来。
2. **整理**：对收集到的信息进行分类和整理，根据任务的性质、截止日期和优先级进行排序，确保每项任务都能得到适当的处理。
3. **组织**：将任务分解为可执行的行动步骤，并安排在合适的时间进行。这可能包括设定提醒、创建子任务或计划特定时间段来完成任务。
4. **回顾**：定期检查和回顾任务列表，确保没有遗漏，并根据需要调整优先级和计划。
5. **执行**：专注于当前手头的任务，一次只做一件事，直到完成。执行过程中可以使用番茄钟等工具来提高专注力和效率。

通过 GTD 方法，个人可以有效地管理自己的时间，减少工作和生活中的压力，从而提高生产力和生活质量。GTD 强调的是“记录”和“执行”之间的平衡，确保所有任务都被妥善管理，而不会让大脑负担过重。

这套流程本身并不复杂，难点在于长期维持，而不在于理解。

这其实类似于对 Task 进行微分操作找出测度并且按照不同类别归类再进行 Lebesgue 积分的过程(doge)，比较关键的信息点在于，你需要有合理的**分类体系和组织方式**，多次重复的回顾执行，达到高强度的记忆和训练量。这种方法相当传统，大多数高中生和没有打磨过工作流的人也基本会使用这种简单的方法，实际就是制定计划预习复习然后保持专注的一个流程。

但是笔者发现这样一种略微机械的方式并不适用于自己，它对于笔者而言有一些很大的问题。

+ 任务过多时即使进行了外部的记录仍然会不断回想，无法达到减轻焦虑的作用
+ 这种工作方式无法很好地控制自己的任务量，也就不能控制好自己的效率
+ 专注执行也有可能错过短暂的机会，如一些课程，一些讲座和活动等
+ 变数过多，**调整优先级十分复杂**
+ 兴趣广泛的人会不断引入新的 todolist 导致体系崩坏
+ 没有给出一个完整的做待办的公式方式，也就是**不够具体**

> 新的一年额外增加一点，作为一个可能具有 ADHD 的爱好学习的人，不太能够让自己完全按照一个线性的计划进行，那么交替地进行不同的任务来计算总量可能是一个更加合适的方法。

这些问题说明，「管理任务」这一层本身并不能带来效果，真正起作用的是更底层的东西：怎么学、以什么状态学、怎么练。

### 自学

**自学的效率应该是最高的**，并且在自学方式中阅读的效率要大于网课，在内容一致的情况下优先选择阅读，但是如果是 61A 那种阅读和网课都有的情况可以先看网课有个初步了解，再去看书，一方面阅读消耗的精神力比较大，高强度的学习难以持久，另一方面看视频网课是可以比较放松的，可以比较好地维持自己的状态，然后延长学习时间。

> 这一条经过检验我认为十分正确

一定不要犹豫，老师教得太烂了就一定要自学，大多数老师教的都不如自学！

> 一年后改编：所有老师教的都不如自学，老师唯一有用的就是对于你初学学过一遍之后，看看他能不能给出一些更高层面的思维指引

学习方式确定之后，能不能坚持下来，很大程度上取决于状态。

### 心态处理

首先要解决焦虑问题。如果把人生归结为资源有限的运筹学最优化问题，那么如何在最短时间内得到量化分数最高的方案并且完成，就是本工作流的基本思想。因此需要进行优先级分类和一些细节的直接给出，**在细碎的事情上思考得越少，用来工作的时间也就越多了**。这一点需要一些补充，在最近经过很多事情之后，人生对于我而言已经不止是优化问题了，享受生活的意义更加重要了。

> 已经开始享受 Gap Year，实现 WLB(Work Life Balance)

需要先认清一点，就是你所处的环境里，人群的能力应呈现基本的正态，并无异常值，也就是所谓天才(genius)，这种异常值应当不会和你处于同一个环境（统计学基本原则）。远离宏大叙事也是摆脱焦虑的一个很好的手段，很多人会用所谓社会学，心理学来高谈阔论，实际上按照我的观察不管是什么环境，只要是超过 30 个人的系统（30 这个数字可以参考生物统计），一定有超过 8 成的白痴，1 成的普通人，还有稍微聪明一些的普通人(No Genius!)

再然后是**克服强迫症和完美主义**的问题，我测出来的 MBTI 是 INTJ，虽然我并不是很相信这些东西，但是我确实有很强的完美主义倾向，但是在大量的尝试中发现，这种心态虽然可以帮助克服拖延，但也同样会增加内耗，可以通过设定基本目标、更高目标和完美主义目标的多目标方式改善，只要完成了设定的基本目标就可以放松一下。因此本文的行文组织也并不是非常完美，而是由比较多的经验主义和小型系统构成的。

最后是业余爱好，业余爱好的数目尽量**不要超过三个**，否则会对整个体系造成很大的冲击，无法完成基本的任务量，也无法很好地享受业余爱好，**作业最好当堂完成，项目最好写出完整的工程 workflow**。

状态理顺了，接下来才是把手放上去。

### 实践训练

这点应当是整个工作流里最重要的，也就是**系统地训练自己的实践能力**，在实践的过程中得到的进步也是最快最大的，没有之一，例如**对于数学课来说做题就是掌握和巩固的最佳手段**。

+ 习题集的完成
	+ 不看答案
	+ 摘取重要习题反复思考并加上 `LaTeX` 整理
	+ 纸上演算和书写
+ 看书
	+ 先看完，有了整个 overview 之后再写笔记，否则容易演变为抄书
	+ 至少要先看两个 Chapter，否则很容易弃坑
+ 写 Project
	+ 做一个项目，可以是复现也可以是创新
	+ 一定要提高自己的码量

需要注意的是，用到的和产生的所有文件应当每周备份到硬盘、网盘以及基本的本地存储，也就是**备份意识**

> [!tip] 完成度提高秘诀
> 专注做好一件事，比如在完成作业后直接 ALL IN 一门课先将那门课学通，学完，然后心里有底了再去学下一门课，这样有利于自信的培养和笔记书写不会那么的冗余。

> [!info] 时间划分
> 将一天划分为三个部分 上午 下午 晚上 尽可能地保证自己的作息正常，不要熬夜也不要不睡觉不休息的干活

上面讲的都是做事层面的训练，而做事时手上用的工具同样会反过来塑造习惯，这就引出了下面这一节。

### 键盘流

额外单开一节来记录这一年的键盘流生活，首先是我已经日常使用 `Linux` 系统一年了，相关的文章可以参考 [Linux 使用一周年纪念](https://www.eurekaimer.icu/blog/posts/summary/linux-%E4%BD%BF%E7%94%A8%E4%B8%80%E5%91%A8%E5%B9%B4%E7%BA%AA%E5%BF%B5/)，并且由于 `Linux` 的特性，我对 Shell 的使用也逐渐上手了；其次是安装了一些键盘流的开源软件，比较重要的就是 `Sioyek` 这个基本仿照 `vim mode` 实现的阅读器，很大程度上启发了我对软件的设计理念，我今年很多设计作品里都尽量使用了键盘流的模式，尽量保证鼠标在使用过程中零参与；对于键盘流的完全拥抱主要是在今年（2026 年）的暑假，大量的寻找和安装优秀的 `Neovim` 插件并且练习盲打，使得我目前的手速达到了一个可以使用的程度，并且得益于 `Neovim` 丰富的软件生态，我当前的生产环境和工作环境已经被我配置得极其舒适，我连 `VSCode` 都不想打开了！

+ **`Linux` 作为工作流的底座**：简单的内核和文件系统让整个系统是可读、可改、可脚本化的，好用的 Shell 又把这套能力直接搬到键盘上，而高度定制化的桌面可以让分屏、切窗口、启动应用都不再需要鼠标参与，我这里用的就是一个支持 vim-mode 的平铺式窗口管理器 `Niri`。三者叠在一起，效率的提升是实打实的，这也是我最终把 `Windows` 踢出自己的使用生态、把台式机也转向 `CachyOS` 的原因。
+ **键盘流的设计理念**：如果你对于 `Vim` 多少了解，或者 `Emacs` 等其他类似的编辑器有了解，就会知道这些工具从创造之初就是秉持着尽量让用户完全依赖键盘工作，从而减少鼠标对于灵感的毁坏。通过减少鼠标的使用极大地加快了开发速度，长时间使用之后，我也配置出了一套自己的快捷键体系。
+ **盲打的练习路径**：先在 `keybr` 上把键位映射练熟，再到 `monkeytype` 上练速度与准确率，`10fastfingers` 则用于测速对比。上面提到的「练习盲打」走的就是这条路，练到手速够用之后，键盘流才真正跑得起来。
+ **`Neovim` 的轻量与快速**：我的配置基于 `Neovim` 0.12 的原生能力加上 `lazy.nvim`，主题是 Kanagawa Wave，`<leader>` 就是空格键；常用入口包括 `<leader><space>` 智能查找、`<leader>e` 文件树、`<leader>ff` 查找文件、`<leader>fg` 全文搜索、`<leader>mr` 切换 `Markdown` 渲染、`<leader>mi` 切换图片显示，整个编辑过程都在终端里完成，不需要离开终端。如果想把 `Neovim` 配成一个完整的 IDE，可以参考 [Learn How To Use NeoVim As an IDE](https://programmingpercy.tech/blog/learn-how-to-use-neovim-as-ide/) 这篇教程。
+ **替换 `Obsidian` 的应用场景**：现在的分工是，撰写笔记（Lecture Notes、阅读笔记）都在 `Neovim` 内写 `Markdown`，`Obsidian` 退化为成品的预览工具与文件管理工具。之所以选 `Markdown`，看中的就是它能把想法快速记下来的轻量格式。

+ Typing websites
	+ [tenfastfingers](https://10fastfingers.com/)
	+ [keybr](https://www.keybr.com/?utm_source=chatgpt.com)
	+ [monkeytype](https://monkeytype.com/)

这套东西几乎没有一样是从课堂里学来的，这也牵出了理论篇最后要讨论的问题。

## 实践

经过了将近六个学期的大学生活，笔者痛定思痛决定将自己目前所有的工具和技能全部合并为一套体系，也就是下面的工作流 5.2，之前几种工作流的问题都尝试进行了解决，希望能对读者也有所帮助。

### 问题总结

> 抓住事物的主要矛盾，作为抓手来解决问题是事半功倍的。

如果要迭代出更强，更有效的工作流，就需要先明确先前的工作流为什么不令人满意，找出存在的问题，想出相应的对策，然后逐步更新，下面是笔者觉得原先工作流存在的一些问题。

+ 工具过多，不够统一，没有办法将所有的资料很好地集成在一个终端上(All in One)，但是全部的内容堆积在一个软件上在软件工程上又是几乎不可能且不可行的，这会导致极致的臃肿和低效。
+ **造轮子的时间比使用轮子的时间还要长**，具体表现在 `Obsidian` 的使用不够多，但是前端美化却花了比较多的时间，还有就是 `LaTeX` 和 `Markdown` 文本的不统一也花费了比较多的时间，迁移到 `Neovim` 之后这个问题减轻了很多
+ 纸质笔记和电子笔记无法**相辅相成**的问题，最后得到的方案是使用纸质笔记帮助理解，但最终一定要生成一份电子版的笔记用于存档和归档
+ **行动力太低**，得到的成果太少，但是思考工作流的时间反而太多，这是一个常见的毛病，也就是过度地沉迷于方法论而忘记去解决原本的问题
+ 患得患失，犹豫不决，体现在对于工具链的使用和选择上，最后得到的解决方案是，抽出一定的时间进行 AB Test，最后得到结论，根据需求导向去选择合适的工作流
+ ...

### 解决方案

针对上面的问题，目前的处理方式如下。

+ 这里我将目前正在使用的所有软件和工具罗列如下，方便整理
	+ ~~`VSCode+LaTeX`~~ 实际上这个工作流现在也不怎么用了，更多是通过 LLM 根据我之前的模板然后撰写好对应的 `LaTeX` 代码之后就可以使用 shell 命令进行编译了，得到最后使用的 PDF 文件并且已经相当美观
	+ ~~`Obsidian/Typora+Markdown`~~ 这是大学前三年（或者说两年半）琢磨出来的最大的成果，最后出于对轻量和键盘流操作习惯的追求舍弃了，目前更多的使用 `Neovim` 配合自己安装的插件，`Obsidian` 目前已经作为一个成品的预览工具和文件管理工具使用了。
	+ `Anaconda`+`Jupyter Notebook` 已经完全舍弃 `Conda`，转而使用 `uv` 的虚拟环境配合 `Jupyter Notebook/Lab` 相关的包来进行 `ipynb` 文件的撰写
	+ `PicGo`+`Typora` 的图床建立 这个方案目前依然在使用，虽然也有尝试过 `PicList` 等等，但是还是这个方案最为简洁并且支持多端同步，目前在两台 `Linux` 机器上也是如此使用
	+ ~~`SimpleTex` 的 OCR 识别~~ 已经变成时代的眼泪，甚至不如使用低费用多模态模型内置的 OCR 模型
	+ ~~个人博客(`MkDocs`)~~ 由于 `MkDocs` 已经不维护了，转而使用 `zensical`，但是在折腾的过程中接触到了 `Fuwari/Firefly` 等成熟美观的 `Astro` 框架，最后设计了三个站点进行管理，如果后续还有做学术的打算应该还会上线一个学术主页作为伪装
	+ `GitHub` 仓库的备份 很好的一个方案，仍然活跃，但是对于图书馆和其他重要的资料仍然使用三次备份原则进行
	+ ~~平板上的笔记软件(GN5)~~ 几乎已经不使用平板，完全变成一个玩具和阅读器使用了，用于观看一些课程（但是我并不是一个喜欢听别人讲的人，因此主要作用还是阅读书籍和讲义）
	+ ~~一块 1T 的固态硬盘~~ 升级到两块，装载番剧和电视剧以及重要的书籍资料
	+ ~~百度网盘的会员容量 6T~~ 当前的会员等级已经达到了 1000T
	+ 电子书的资源(Zlib/Anna) 非常好的方案
	+ 电子书阅读器 `KOReader`、`Sioyek`、`Readest`，其中常用的只有前两个，第三个主要用于对一些轻小说的同步进行管理，得到一个快速能用的版本，另一方面是手机端的支持确实做得比前面两个好一点
+ 简约化 `Obsidian` 的布局和管理方案，得到一个命名体系（详见 [文件命名原则](#文件命名原则)）
	+ 基本遵循一定的命名逻辑
+ ~~**全部改为无纸化笔记**，纸质的仅剩老师要求的纸质版作业和演算用的草稿本和一些简单的预习笔记~~，这点已经做到了
+ ~~使用 Todomate+不背单词，相互 push~~（已经失败，主要是因为工作周期不规律）非常糟糕的计划，后续自己撰写了一个项目 `lexigraph` 和 `kana` 用于背诵英文和日语。
+ **写周报，~~月报~~**，总结进度，制定计划（**XB Inequality:= 总结>计划**）对于月报我认为没有必要，只需要知道自己一周之内要做成什么事情，即便是比较粗糙的概念即可，如果要对于每一天都做到完整的复盘实际是比较难以养成的习惯，刚开始应该以周为单位会比较好。

### 文件命名原则

> [!abstract] 命名体系
> 为了方便管理起见笔者总结了一套针对所有（数学-统计学-计算机）的命名原则，整体遵循「课程/项目 → 章节或课次 → 具体文件」的三级结构，同一内容只保留一套分类体系，避免重复建库。

+ 课程笔记（Lecture Notes）
	+ 课程主页：`课程名称(Lecture).md`，作为该课程的入口与索引（如 `数理统计(Lecture).md`、`随机过程(Lecture).md`、`实变函数(Lecture).md`）
	+ 章节页：统一放在课程目录下的 `Assets/` 中；按老师风格二选一，同一门课内保持一致
		+ 按章节讲授：`第N章 主题.md` 或 `Chapter N 主题.md`
		+ 按课次讲授：`LectureN 主题.md` 或 `LecN 主题.md`
	+ 习题课（Office Hour）：以 `OH` 标记，与正课笔记同目录
	+ 作业：一般不需要加前缀，使用 `HW1` 即可，可以直接 push 到个人博客或者公众号上
		+ `LaTeX`：可以先在 `Obsidian` 上用 LaTeX Suite 插件抄写题目后快速编辑套版，识别部分交给多模态模型
		+ `JPG(PNG)`：图片类（纸质作业）可以考虑摘取部分有价值的问题转化为 `LaTeX` 保存
		+ `PDF`：OCR 或者摘取有价值部分改为 `Obsidian` 存储
+ 阅读笔记（Reading Notes）
	+ 以「书名或作者」作为基础，一个特别的标识码作为补充用 `-` 连接，例如 `茆-第五章 统计量及其分布`
	+ 章节名称作为本章节笔记标题
	+ 如果是比较有说服力并且经典的教材可以使用作者的名字，例如 `Folland`、`Stein`、`Durrett`
+ 公开课（MOOC）
	+ 课程主页：`课程代码.md`（如 `CS61A.md`、`CS231n.md`）
	+ 课次页：`课程代码-Week-N.md` 或 `课程代码-LectureN 主题.md`，同样放在 `Assets/` 下
+ 计算机类课程的其他常见类型
	+ `Lab`
	+ `Problem Set`
	+ `Project N-名称`
	+ `Week N`
+ 标签
	+ 每份笔记首行写类型标签，便于检索与聚合，例如 `#工作流`、`#总结`、`#Linux`、`#工具`

### 任务排序

命名原则解决的是东西放在哪里，而每天真正要决定的，则是先做哪一件事。

制定计划的部分：提前一天先想好第二天的主要目标，然后按照优先级排序，需要注意的是 `不要随意添加任务`，要额外添加的任务必须最早在后一天加入，并且要保证优先级高的任务先完成。

日常的 routine 类任务优先级可以提到最高，当天要上交的作业提到第二高，关系个人的专业课学习次之，如果是个人培养计划外的非专业课学习再次之（CS、日语、复变函数）。

> [!tip] 优先级排序系统案例
> 1. 日常学英语
> 2. 锻炼身体
> 3. 完成作业
> 4. 理论专业课学习和代码实践
> 5. 非本专业课学习
> 6. 杀戮尖塔
> 7. 聊天和刷短视频

> [!tip] 集中力量

### 记录笔记

任务排好之后，学习过程中沉淀下来的东西要落到笔记上。

关于笔记的问题，我思考了非常久，首先明确的就是基本上学习离不开笔记，因为迟早会忘记，笔记可以帮助你更快地回到掌握程度比较好的时候，也就相当于一个成长加速器，也可以储存一些技巧和算法的细节，方便日后查询。

然后关于日常学习所书写的笔记，例如**数理统计和运筹与优化、实变函数**这些明明很重要的核心专业课，老师的参照物大多数却只有课本和 PPT。早先为了保证良好的连贯性，这类笔记一般会选择使用 pad 而不是电脑作为记录工具；到现在平板已经完全退化成阅读器，所有的笔记都统一在电脑上记录，这就更需要提前设计好自己的宏和插件，保证速度可以跟得上。

如果对某些课程自己额外阅读了一些书籍，有一些新的想法，如果不是结构和体系上很大的区别，或是那本书过于著名和有效，都建议直接修改在原本的 Lecture Notes 中

> 这里存在一些问题：我出于规范的分类目的，总是将对于某本书的笔记单独创建一个文件夹出来，但是问题在于，那个领域/那门课应该是一个统一的整体，不同的书籍即便覆盖面和写法不同，所涵盖的内容总还是大同小异的，这种做法会导致大量的内容重复和时间的浪费

最后得出的解决方案是以一本书为标准，最后将从其他书本那里获得来的知识在标准的基础上打补丁和完善。

为了方便发布，日常的作业多可以使用 `LaTeX` 进行书写，例如数学分析、高等代数、实变函数；数理统计和运筹与优化由于其题目质量不高、题量又比较大或是做法形式不易展现（单纯形表说的就是你），所以采用的是学习后再在 `Obsidian` 上记录的方式。

> 建议尽量使用 `Markdown` 记录然后使用 LLM 转换，因为 `Markdown` 格式是一种能够非常好地将思想快速记录的轻格式，而且写起来也很容易

> [!abstract] 记录原则
> 1. 不要抄书是伪命题，因为初学时不太可能完全按照自己的方式说清一个定理或方法的全部内核，但是书本由于它的多次阅读和多批教学，正确性和深度比较有保证，因此抄书确实可以增加理解，只是要注意在后期更新自己的 notation 即可，达到理解并可以运用的程度才是最重要的。
> 2. `LaTeX` 笔记可以分段上传，不要想着全部写完后一次上传，这样容易拖延，写完一章的就可以上传到网站或是公众号和其他平台上
> 3. 不要乱搞 open problem
> 4. 不要乱读一些很老的参考文献

### 总结思考

笔记是过程性的记录，定期的回顾与总结则是另一件事。

目前主要是写周报和 blog，

周报中包含：

1. 本周完成的任务
2. 下一周要完成的任务
3. 思考与原本计划的差距
4. 得到一些结论，找到优化点，然后可以记录，积累到一定程度**再回头思考是否合理**
5. 再次迭代工作流（会自我更新的东西才不会落伍）

一定要注意重新看自己的周报，从中发现共同的问题然后进行修改
